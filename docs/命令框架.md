# 命令框架

本文描述项目自研的命令框架，该框架负责命令与会话的生命周期管理，即处理诸如如何与 NoneBot 通信，一条消息如何被路由到特定会话中的特定命令，命令如何保持或改变状态、并发与终止等此类问题。

> 为避免混淆，本文描述属性时，除了源代码，将都会省略属性名前面的 `_` 并申明该属性的外部权限。

---

## 1. 概览

### 1.1 框架主体

| 模块 | 文件 | 类 | 职责 |
|---|---|---|---|
| 驱动与路由 | `handlers.py` | `-` | 命令注册、消息路由、启停钩子 |
| 会话管理 | `session.py` | `BotSession` | 按 `(群, 用户)` 隔离会话，通过 `pid` 维护命令槽位与前台指针 |
| 命令管理 | `command.py` | `BotCommand` | 命令实例的状态机、子任务、缓存、取消与终止 |

### 1.2 框架拓展模块

| 模块 | 文件 | 接入方式 |
|---|---|---|
| 参数解析 | `parser.py` | `_init_parser()` 定义语法，`_legal_case()` 校验 |
| 权限 | `permissions.py` | `_check_perm()` 查询权限条目 |
| 配置 | `config.py` | `config.cache` / `config.data` 等路径 |

### 1.3 框架使用者

| 模块 | 文件 | 使用方式 |
|---|---|---|
| 具体命令 | `commands/*.py` | 继承 `command.py` 的 `BotCommand` |

### 1.4 框架不变量

“不变量”指框架在任何时刻都保证成立的规则：

1. 同一个 `(group_id, user_id)` 至多一个 `BotSession` 实例。
2. 同一个 `BotSession` 的同一个 `pid` 至多绑定一个命令实例。
3. 一条命令消息至多被一个命令实例消费（由 matcher 的 `block` 与路由保证）。
4. 命令的生命周期由 `unlock()` 显式结束。

### 1.5 结构图示

```
                    QQ 客户端
                       │ OneBot v11
                       ▼
                 NoneBot2 driver
                       │ 事件
                       ▼
              ┌───────────────────┐
              │    handlers.py    │  on_command / on_message
              │  命令注册 + 路由  │  on_startup / on_bot_connect / on_shutdown
              └─────────┬─────────┘
                        │ (group_id, user_id)
                        ▼
              ┌───────────────────┐
              │    BotSession     │  每个 (群, 用户) 一个
              │ commands: pid→命令│
              │  curpid           │
              └─────────┬─────────┘
                        │ run(args) / roger(event)
                        ▼
              ┌───────────────────┐
              │    BotCommand     │  每个 pid 一个实例
              │   _argv 状态机    │
              │   子任务 / 缓存   │
              └───────────────────┘
```

- `Message` 是输入，`BotSession` 是容器，`BotCommand` 是状态机。
- 一个会话可以同时容纳多个命令，每个命令占据一个 `pid`。
- `curpid` 决定"当前前台"是哪个命令：新命令落在该槽位，普通消息也投递给它。

## 2. 会话

### 2.0 属性一览

| 成员 | 类型 | 说明 | 外部权限 |
|---|---|---|---|
| `sentinel` | 类属性，`object` | 单例哨兵 | 私有 |
| `objs` | 类属性，`dict[str, dict[str, BotSession]]` | 会话实例的字典 | 私有 |
| `group_id` | 实例属性，`str` | 群 ID | 只读 |
| `user_id` | 实例属性，`str` | 用户 ID | 只读 |
| `curpid` | 实例属性，`int` | 前台 | 读写 |
| `commands` | 实例属性，`dict[int, BotCommand]` | 命令实例的字典 | 只读 |

### 2.1 身份

每个会话与 `(group_id, user_id)` 构成单射，即一个二元组对应至多一个会话实例。

其中 `group_id` 分为三种情况：

| 场景 | `group_id` |
|---|---|
| 群聊 | 群号字符串 |
| 私聊 | 固定字符串 `"private"` |
| 后台服务 | 固定字符串 `"public"` |

这套机制保证同一个用户在同一个群里发命令将会总是命中同一个 session；换群或私聊，或让不同用户来操作，则是另一个 session。

### 2.2 注册表

`BotSession` 用类级字典 `objs` 维护所有会话：

```python
_objs: dict[str, dict[str, BotSession]]   # group_id -> user_id -> session
```

| 方法 | 行为 |
|---|---|
| `make(group_id, user_id)` | 工厂方法，会话存在则返回该会话，不存在则创建并注册会话 |
| `get_obj(group_id, user_id)` | 查询会话，若会话不存在则返回 `None` |
| `get_group_objs(group_id)` | 返回某群下所有用户会话 |
| `get_sessions()` | 返回所有会话 |
| `rm_obj(group_id, user_id)` | 将二元组对应的会话从注册表移除 |

### 2.3 创建会话

`make()` 会尝试创建并注册会话，是创建实例的唯一方式。`__init__` 通过要求调用方向 `_internal` 参数项传入内部哨兵`sentinel`来保证这一点：

```python
def __init__(self, group_id: str, user_id: str, *, _internal=None):
    if _internal is not self._sentinel:
        raise TypeError(...)
    ...

@classmethod
def make(cls, group_id: str, user_id: str):
    obj = cls.get_obj(group_id, user_id)
    if obj is not None:
        return obj
    cls._objs.setdefault(group_id, {})[user_id] = cls(
        group_id, user_id, _internal=cls._sentinel    # 传入哨兵
    )
    return cls._objs[group_id][user_id]
```

### 2.4 命令槽位

`pid` 是命令实例在会话内的槽位编号，`BotSession` 通过 `commands` 记录本会话中的命令：

```python
_commands: dict[int, BotCommand]   # pid -> command
```

字典的键即 `pid`，一个 `pid` 同时只放一个命令。`pid` 的正负遵循以下约定：

| pid | 用途 | 例子 |
|---|---|---|
| `> 0` | 用户直接调用的命令 | `/shitpost`、`/convert` |
| `0` | 会话管理命令 | `/session`（注册时固定 `_pid=0`） |
| `< 0` | 命令内部创建的嵌套命令 | `/help` 内部调用的 `md2pic` |

### 2.5 前台

`curpid` 是一个特别的 `pid`，被称为前台。前台对应着当前唯一一个可接收用户输入的命令（不考虑会话管理命令），同一会话中的其他命令在后台运行。

- 新会话默认 `curpid = 1`。
- 根据 `pid` 的约定，`curpid` 必须 `>0`。
- `BotCommand.make()` 默认尝试占用当前会话的 `curpid`，（若传入 `_pid` 参数，则会改为尝试占用它）。
- 可用命令 `/session switch <pid>` 修改 `curpid` 从而切换接收输入的命令（见 2.8）。
- 也就是说，本质上 `curpid` 只影响两件事：
  1. 新命令默认将会尝试落在哪个槽位；
  2. 当前会话接收到的信息将会传递给哪个命令。

### 2.6 生命周期

```python
session = BotSession.make(group_id, user_id)   # 创建或获取对应会话
command = SomeCommand.make(bot, session)       # 尝试创建命令实例（见 3.1）
command.unlock()                               # 弹出commands中对应命令后调用 session.release() 尝试销毁会话
```

`release()` 只在 `commands` 为空时销毁会话，即会话的生命周期由"最后一个命令是否退出"决定：

```python
def release(self):
    if self._commands == {}:
        BotSession.rm_obj(self.group_id, self.user_id)
```

### 2.7 后台常驻会话

由于后台常驻命令没有真实的群聊/用户，本项目中使用伪身份作为标识：

```python
session = BotSession.make("public", "autoreply")
command = BotCommandAutoReplyMain.make(bot, session, _pid=session.curpid)
```

其中，任何非命令信息会被分发至 `public` 会话下特定命令的 `roger` 方法（见 4.4）。

### 2.8 会话管理命令

`/session` 是注册时固定仅尝试占用 `pid 0` 的特殊命令，无论前台是否被占用，都可以使用该命令管理当前会话里的其他命令：

| 子命令 | 实现 |
|---|---|
| `/session switch <pid>` | 设置 `curpid`（由于 `pid` 的约定， `<= 0` 的值将会被忽略） |
| `/session info` | 输出 `curpid` 与 `commands` 的 `pid → name` 映射 |
| `/session stop` | 停止并释放前台命令 （见 3.3 和 3.5） |

该命令为单次单向运行状态机（见 3.2），故 `pid 0` 不会长期占位。

## 3. 命令

### 3.0 属性一览

| 成员 | 类型 | 说明 | 外部权限 |
|---|---|---|---|
| `sentinel` | 类属性，`object` | 单例哨兵 | 私有 |
| `name` | 类属性，`str` | 命令名称 | 只读 |
| `bot` | 实例属性，`Bot` | 机器人实例 | 只读 |
| `session` | 实例属性，`BotSession | None` | 会话实例 | 只读 |
| `group_id` | 实例属性，`str` | 会话的群 ID | 只读 |
| `user_id` | 实例属性，`str` | 会话的用户 ID | 只读 |
| `pid` | 实例属性，`int` | 命令槽位 | 只读 |
| `cache_dir` | 实例属性，`Path` | 命令缓存目录 | 私有 |
| `argv` | 实例属性，`list[str] | None` | 当前命令参数 | 只读 |
| `parser` | 实例属性，`BotArgParser` | 命令参数解析器 | 私有 |
| `run_tasks` | 实例属性，`set[asyncio.Task]` | 所有的 `run` 任务 | 只读 |
| `roger_tasks` | 实例属性，`set[asyncio.Task]` | 所有的 `roger` 任务 | 只读 |
| `inner_tasks` | 实例属性，`set[asyncio.Task]` | 所有的子任务 | 私有 |
| `inner_cmds` | 实例属性，`list[BotCommand]` | 所有的嵌套命令实例 | 私有 |

### 3.1 创建命令

与 `BotSession` 一样，`BotCommand` 及其子类用相同的方式阻止直接构造，只能通过 `make()` 来尝试占用 `pid` 并创建实例，若 `pid` 被占用，则返回 `None` 后交给上游处理，否则占用该 `pid` 并创建实例：

```python
@classmethod
def make(cls, bot, session, *, _pid=None):
    if _pid is None:
        _pid = session.curpid
    if session.commands.get(_pid):
        return None            # 槽位已被占用
    return cls(bot, session, _pid=_pid, _internal=cls._sentinel)
```

`__init__` 除了会定义与设置属性与防止直接构造外，还负责在 `session` 内注册命令：

```python
    def __init__(self, bot: Bot, session: BotSession, *, _pid: int, _internal=None):
        ...
        session.commands[_pid] = self
```

### 3.2 命令参数与状态

本质上，`BotCommand` 构成一个有限状态机，包含唯一的状态标记属性 `argv`，也就是命令此时的参数串：

```python
_argv: list[str] | None
```

即：对于同一命令，状态相同当且仅当 `argv` 相同。

作为命令状态时，`argv`  含义如下：

| 值 | 含义 |
|---|---|
| `None` | 未运行或已结束 |
| `not None` | 运行中，保存启动参数 |

`argv` 通常由传入`run()` 的`Message`信息（见 4.2）来决定，子类在 `run()` 里自行解释 `argv`，两个例子如下：

- 单次单向运行状态机：设置 `_argv` -> 执行 -> `unlock()`，下次调用是全新实例。
- 多次单向运行状态机：设置 `_argv` -> 执行 -> 实例留在会话中等待后续命令 -> 收到后续特定的命令 -> 执行 -> `unlock()`。

### 3.3 `run()` 与 `roger()`

| 方法 | 触发条件 | 用途 |
|---|---|---|
| `run(args: Message)` | 命令名匹配 | 处理命令参数，驱动状态迁移 |
| `roger(event: MessageEvent)` | 收到普通消息 | 收集交互内容（图片、文本等） |

二者在子类定义时会被自动包装，基类在模块末尾时单独包装：

```python
def __init_subclass__(cls):
    if "run" in cls.__dict__:
        cls.run = _cancellable_run(cls.run)
    if "roger" in cls.__dict__:
        cls.roger = _cancellable_roger(cls.roger)
```

```python
BotCommand.run = _cancellable_run(BotCommand.run)
BotCommand.roger = _cancellable_roger(BotCommand.roger)
```

包装器负责以下任务：

1. 把当前 `asyncio.Task` 录入 `run_tasks` 或 `roger_tasks`，供 `/session stop` 与 shutdown 取消；
2. 阻断 `CancelledError` 异常的向上传播。

`run_tasks` 与 `roger_tasks` 分别记录正在执行的 `run()` 与 `roger()` 任务：包装器在任务开始时加入、结束时移除。`/session stop` 和 shutdown 通过 `task.cancel()` 向两个集合中的任务来发送 `CancelledError` 异常来中断命令。

### 3.4 状态保护

`_guard_state()` 方法定义了状态机在某状态下可被什么新参数串改变状态，通过返回布尔值来告知上游是否该允许命令的继续执行，故通常会在 `run()` 中参数解析完毕后被调用，当返回 `False` 时通常伴随着向请求者回复错误信息的副作用。

默认实现是单次单向运行状态机的对应行为，即只要命令正在运行，任何新 `run()` 的调用都会被拒绝：

```python
async def _guard_state(self, *args, **kwargs):
    if self._argv is not None:
        ... 回复"命令 X 正在运行" ...
        return False
    return True
```

对于其它不同行为的状态机，往往需要覆盖重写该方法以符合其行为，例如：

```python
# convert：运行中允许 stop，未运行时拒绝 stop
async def _guard_state(self, subcmd=None):
    if self._argv is not None and subcmd == "start":
        ... 拒绝重复 start ...
        return False
    if self._argv is None and subcmd == "stop":
        ... "尚未开始" ...
        return False
    return True
```

### 3.5 终止：`unlock()`

`unlock()` 用于命令的结束工作，它会取消下游任务与删除缓存，并断开与会话的相互联系：

```python
def unlock(self):
    if self._session is None:
        return
    for task in self._inner_tasks:                 # 取消子任务（见 3.6）
        if not task.done():
            task.cancel()
    for cmd in self._inner_cmds:                   # 递归解锁嵌套命令（见 3.6）
        cmd.unlock()
    self._rm_cache()                               # 清除命令缓存目录（见 3.7）
    self._session.commands.pop(self._pid, None)    # 解除会话对自身的引用
    self._session.release()                        # 尝试销毁会话
    self._session = None                           # 解除自身对会话的引用
```

### 3.6 子任务与嵌套命令

**子任务**：

命令可用 `_create_task()` 方法来创建自己的子任务，子任务会被录入 `inner_tasks` 中，并在完成后自动退出：

```python
def _create_task(self, coro):
    task = asyncio.create_task(coro)
    self._inner_tasks.add(task)
    task.add_done_callback(self._inner_tasks.discard)
    return task
```

**嵌套命令**：

命令可用 `_create_cmd()` 方法来创建自己的嵌套命令，该方法负责寻找合适的 `pid` 并在其上尝试创建命令，并在成功后将其录入 `inner_cmds` 中：

```python
def _create_cmd(self, cls: type):
    if self.session is None:
        return
    _pid = -1
    pids = self.session.commands.keys()
    while _pid in pids:
        _pid -= 1
    cmd = cls.make(self.bot, self.session, _pid=_pid)
    if cmd is None:
        return
    self._inner_cmds.append(cmd)
    return cmd
```

按照约定，由此方法创建的嵌套命令均为负数 `pid`；由于嵌套命令已被录入 `inner_cmds` 中，在本命令执行 `unlock()` 时会递归终止它们。

### 3.7 缓存目录

每个命令实例预定了自己的缓存目录 `cache_dir`，由 `group_id`、`user_id`、`pid` 共同决定：

```
_cache_dir = config.cache / <group_id> / <user_id> / <pid> /
```

为避免不必要的 IO 操作，缓存目录需要手动用 `mkdir` 创建；命令执行 `unlock()` 时会调用`_rm_cache()` 删除它。

### 3.8 基类的默认行为

`BotCommand` 本身注册为 `otherwise` 兜底命令（见 4.4）：

```python
async def run(self, args):
    if not self._check_perm("otherwise"):
        self.unlock()
        return
    await self.send_msg("无效命令，请输入/help获取帮助。")
    self.unlock()
```

## 4. 事件路由

### 4.0 背景知识

| 概念 | 说明 |
|---|---|
| matcher | NoneBot 中“监听某类事件并处理”的对象 |
| `on_message()` | matcher 注册器，创建仅响应信息事件的 matcher |
| `on_command(name)` | matcher 注册器，创建仅在信息事件开头为指定命令开头（默认为 `/`），命令名为 `name` 时响应的 matcher |
| `priority` | matcher 注册器的参数之一，决定多个 matcher 的处理顺序，数值越小越先 |
| `block` | matcher 注册器的参数之一，决定是否拦截接收到的事件，为 `True` 时事件不再被传递给后续的 matcher |

### 4.1 命令注册

本项目的命令通过 `cmd_register` 注册：

```python
def cmd_register(name, cmd_cls, *, priority=2, block=True, _pid=None):
    matcher = on_command(name, priority=priority, block=block)

    async def _handler(bot, event, args=CommandArg()):
        await cmd_handler(bot, matcher, event, cmd_cls, args, _pid=_pid)

    matcher.handle()(_handler)
```

其中 `CommandArg()` 是 NoneBot 的参数注入，表示命令名之后的文本。

### 4.2 事件处理函数

`cmd_handler(bot: Bot, matcher, event, cmd_cls, args, _pid)` 负责解析事件并尝试创建命令实例，流程如下：

0. 检验传入的类是否为命令类;
1. 解析事件 `event` 的 `group_id` 和 `user_id`；
2. 尝试创建会话与命令实例；
3. 若 `_pid` 对应的命令实例与 `cmd_cls` 不匹配，则向用户发送错误信息后返回；
4. 向参数注入回复消息段；
5. 执行命令实例的 `run(args)` 方法。

```python
async def cmd_handler(bot, matcher, event, cmd_cls, args, _pid=None):
    if cmd_cls not in command_classes: # command_classes 为全局变量，包含了所有命令类
        return

    user_id = str(event.user_id)
    group_id = ... # 若私聊则为 "private"，否则为群号字符串
    cmdname = cmd_cls.get_name()

    session = BotSession.make(group_id, user_id)
    command = cmd_cls.make(bot, session, _pid=_pid)

    if _pid is None:
        _pid = session.curpid
    scmd = session.commands.get(_pid)

    if not scmd:
        ... # 排除 scmd 为 None 的情况（实际上不可能为 None）

    if not command and scmd.name != cmdname:
        ... # 命令不匹配，表示有其它命令正在执行，返回

    reply = get_reply(event)
    if reply is not None:
        args = Message([reply]) + args
    await scmd.run(args)
    await matcher.finish()
```

### 4.3 `roger` 分发

项目维护一个 `on_message` matcher，用于向特定会话前台对应的命令分发非命令信息事件，调用其 `roger` 方法：

```python
@on_message(priority=10, block=False)
async def handle_msg_manager(event):
    sessions = BotSession.get_group_objs("public")
    session = BotSession.get_obj(group_id, user_id)
    if session is not None:
        sessions.append(session)

    for session in sessions:
        command = session.commands.get(session.curpid)
        if command is None:
            continue
        await command.roger(event)
```
根据代码，该 matcher 具备以下性质：

- 按照约定，该 `matcher` 仅会向 `curpid` 上的命令分发消息事件；
-  `public` 会话始终可以接收到所有会话的信息事件；
-  非 `public` 会话只能接收到会话 `group_id`, `user_id` 对应的信息事件；
-  仅发送非命令信息事件由 `priority=10` 以及 `otherwise` matcher 保证（见 4.4）。

### 4.4 命令兜底

项目使用 `otherwise` matcher 来实现命令兜底：

```python
cmd_otherwise = cmd_register("", BotCommand, priority=3)
```

该 matcher 会在命令未匹配时被触发，执行 `BotCommand.run()` 方法，并拦截命令信息事件的传递，保证这类信息不会传给 `roger`。

### 4.5 启动与关闭钩子

| 钩子 | 行为 |
|---|---|
| `on_startup` | 删除并重建 `config.cache`；启动渲染服务 |
| `on_bot_connect` | 初始化 autoreply / shitpost 服务；按 `setting.yaml` 的 `is_auto` 启动 public 会话 |
| `on_shutdown` | 关闭渲染服务；取消所有顶层命令的 `run_tasks` / `roger_tasks` 并递归 `unlock()`；清除 `config.cache` |

## 5. 框架外模块与扩展点

框架通过基类上的几个入口与外部模块解耦：

| 扩展点 | 用途 | 外部模块 |
|---|---|---|
| `_init_parser()` | 构造命令语法时调用，返回值存入 `_parser` | `parser.BotArgParser` |
| `_legal_case(argv)` | 调用 `parser.is_valid()`，失败时向用户回显 `parser.err` | 参数解析 |
| `_check_perm(entry)` | 调用 `get_permissions().check_permission()` 判断当前会话是否具备权限 | 权限系统 |
| `send_msg()` | 处理参数后调用 `msgutils.send_msg()` 向特定会话发送信息 | 消息服务 |
| `config.cache` | 定义 `cache_dir` 时拼接缓存路径 | 配置 |
